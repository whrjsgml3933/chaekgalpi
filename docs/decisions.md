# 설계 결정과 문제 해결

## 느슨한 검색과 보수적인 인물 확정

- **문제:** 입력 이름을 위키 문서 제목과 직접 비교하면 띄어쓰기·기호·별칭·성만 입력한 사례를 놓쳤습니다.
- **변경:** 정규화한 이름, 리다이렉트 별칭, 다른 언어 제목, 책 제목이 등장하는 검색 문맥을 함께 비교합니다. 오타 비교에는 책 제목 근거가 필요합니다.
- **검증:** `인간관계론 / 카네키`의 실제 검색·소개 생성, 이름 표기·동명이인·조회 제한 회귀 테스트.
- **한계:** 외부 검색이 후보를 제공하지 않거나 근거가 부족하면 생성하지 않습니다. 검색 순위만으로 인물을 정하지 않습니다.

관련 코드: [검색·후보 점수](../books/services.py), [회귀 테스트](../books/test_optional.py).

## AI 생성 실패 시 원본 데이터 유지

- **문제:** 외부 API에 사용자 작성 자료의 저장까지 의존하면 인증·한도·모델 지원·네트워크 오류로 글을 잃을 수 있습니다.
- **변경:** 기본 자료를 먼저 저장하고 생성 상태와 결과를 분리합니다. 생성 응답은 JSON 스키마·필드 타입·키워드 수·이미지 형식으로 검증합니다.
- **검증:** 실패해도 Book/Thread가 남는지, 작성자만 재시도하는지, 처리 중 중복 요청을 막는지 확인합니다.
- **한계:** 동기 요청이며 프로세스 중단 시 상태 만료·복구가 없습니다. 작업 큐가 후속 과제입니다.

## 이미지 파일 수명

- **변경:** DB에는 경로를 저장하고 파일 교체 시 이전 커버를 삭제합니다. 기록 삭제 시 파일 정리는 트랜잭션 커밋 후 수행합니다.
- **검증:** 생성 파일 저장·교체·삭제와 연결 모델 연쇄 삭제 테스트.
- **한계:** 로컬 저장소를 사용합니다. DB와 파일 저장소가 단일 원자적 트랜잭션이 되는 구조는 아니므로 운영 환경에서는 보상 처리·정기 정리도 필요합니다.

## 평점과 클릭 영역

- **문제:** 제목 글자만 상세 링크였고, 최대값 제한 없이 평점이 저장됐습니다.
- **변경:** Bootstrap stretched-link와 카드 포커스 표시를 적용하고, 폼·모델 검증에 0~10점 범위를 지정했습니다.
- **검증:** PC·모바일에서 표지·설명·평점 부분 클릭, 키보드 Enter 이동, 범위 밖 값 거부와 10점 저장을 확인했습니다.

## 외부 모델 지원 변경

사용하던 교육 환경에서 DALL-E 3 요청이 미지원 오류를 반환했습니다. 제공자의 실제 응답을 확인하고, 생성에 성공한 gpt-image-2로 변경했습니다. 텍스트 처리는 gpt-5-nano를 유지했습니다. 이미지 생성 결과에는 AI 표시를 넣고 기존 책 표지를 복제하지 않는 프롬프트를 사용합니다.

이 기록은 실제 문제와 구현 선택을 설명합니다. 과거 팀 협업 이력이나 운영 성과를 소급해 만들어 적지 않았습니다.
